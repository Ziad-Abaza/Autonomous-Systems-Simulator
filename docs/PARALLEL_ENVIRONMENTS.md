# Parallel Environments

Four execution backends, selected per run via `env_mode` in the trainer
contract. All four implement the same VectorEnv surface
(`reset_all` / `reset_at` / `step_all` / `set_scenario` / `close`), so
PPO/SAC/DQN runners treat them identically — per-env episode accounting,
terminated/truncated separation, and deterministic per-env reset seeds are
backend-independent.

| env_mode | Isolation | Processes | Transport | Scaling |
|---|---|---|---|---|
| `inprocess` | none | 1 | direct calls | CPU-bound (GIL) |
| `process` | full | N child | `multiprocessing.Pipe` | near-linear per core |
| `tcp` | full | N child | TCP per port | LAN-distributable |
| `tcp_multi` | partial | 1 child | TCP, one port | one sim process, N envs |

## `inprocess` — sequential list

`SyncVectorEnv` wraps a plain list of `SimulationEnvironment` instances.
`step_all` iterates in order — cheapest transport, no isolation. Best for
correctness work and small `num_envs`.

## `process` — `ProcessVectorEnv`

Each env runs in a `spawn`-context child process communicating over a
Pipe (Windows-compatible; worker functions are module-level for
pickling). Step results preserve env ordering and terminated/truncated.
Worker crashes propagate as `WorkerError` with the child traceback —
never a silent hang. `close()` drains pipes then terminates children;
workers also self-close on parent-pipe EOF.

Scenario broadcast: `vec.set_scenario(dict)` issues `SET_SCENARIO` to
every worker; all workers must ACK or the call raises.

## `tcp` — one simulator per env

The orchestrator spawns N `main.py --headless --port` processes via
`HeadlessSimProcessPool`; the trainer connects with one `SimGymEnv`
per port, wrapped in `SyncVectorEnv`. Full process isolation plus a
real serialization boundary — the strongest correctness guarantee.

## `tcp_multi` — one simulator process, N envs

`HeadlessSimProcessPool(shared_process=True)` spawns a single
`main.py --headless --num-envs N --port P`. `SimServerMulti` binds each
accepted TCP client to its own `SimulationEnvironment` (env-per-
connection); `SyncVectorEnv` holds N clients on the same port. Per-client
reset/step/scenario state is isolated; disconnects return the env slot to
the pool; a full server rejects extra clients.

Use it when process spawn cost dominates (many envs on one host) and you
still want a real IPC boundary.

## Independent seeds

- Env construction seeds: `contract.seed + env_index`.
- Episode reset seeds: derived per env per epoch via the runner's
  `_next_reset_seed(env_idx)` — deterministic across runs and backends.
- Trajectory headers record the exact `episode_seed` (and `env_index`,
  `curriculum_stage_index`) per episode for replay-level provenance.
